**Done, found via the first real CI run (3-OS matrix, ubuntu/windows/macos), set up as part of the git-to-release audit:**
- `assertSafePath`'s containment check hardcoded a `'/'` string prefix (`resolved.startsWith(resolvedRoot + '/')`). `path.resolve()` on Windows returns backslash-separated paths, so that check failed unconditionally on every single call there - `memoryintel update` was completely broken on Windows, rejecting every legitimate write with 'not a recognized Memory Intel file'. Never caught before because nothing had ever run this project's own tests on Windows until this matrix job's first real run. Fixed with `path.relative()`-based containment (`rel.startsWith('..') || isAbsolute(rel)`), which makes no separator-character assumptions at all.


**Also found via that same first CI run:** `isPathClean()`'s caller in `commands/update.ts` built its comparison path with `path.join('.memoryintel', row.file)` - OS-native separators - then compared it against git's own porcelain output, which git always reports with forward slashes regardless of OS. On Windows the two could never match, so every file looked permanently clean, silently accepting compression rows on dirty files instead of rejecting them. Fixed with `path.posix.join`. A third, unrelated issue in the same run: a new test added this session (`still accepts a plan piped over stdin`) hardcoded `/bin/sh -c 'echo ... | cli'` to build the pipe - `/bin/sh` doesn't exist on `windows-latest`, so `spawnSync` returned a null status instead of failing meaningfully. Fixed by using `spawnSync`'s own `input` option instead of shelling out at all - genuinely portable, not just skipped on Windows. All three fixes landed as separate commits so the CI matrix could re-verify each one individually; all three OS jobs are green as of commit e2151f1.
